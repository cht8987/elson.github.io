The Problem

Every note system asks you to think before you capture. That's backwards.

Fourteen years of brand work generates an absurd amount of loose thinking — campaign ideas at midnight, client todos in traffic, expenses scribbled into chat apps. Every productivity tool I tried made the same demand: decide where it goes first. Which folder. Which tag. Which template. The cognitive tax happens at exactly the moment you have the least attention to spend.

So I inverted it. One inbox. Zero decisions. The system figures out the rest — and an AI night butler tidies up while I sleep.

The Core Idea

Throw it in. The OS sorts it out.

The only action the user ever needs is dropping a thought into the Inbox — by text, voice, PDF, or web clip, from desktop or phone. An AI pipeline splits each capture into structured entities and files them into the right place in a five-pillar Markdown vault.

"Locked the project architecture today. Remember to renew the server cert tomorrow. Lunch was RM38."

Everything lives in plain Markdown files I own outright — no proprietary database, no subscription lock-in, readable in any editor for the next 30 years.

What I Built

Not an app. An operating system with six organs.

Each layer is replaceable, extensible, and self-hostable. Designed like a brand system: every component has a clear job and a clear interface to the others.

Core · v0.7

🧠 personal-os

The desktop core: a five-pillar vault template, the zero-dependency rtk CLI engine, a custom Obsidian dashboard plugin, and a one-command installer.

Mobile

📱 OSMIND App

The capture terminal in your pocket — text, voice, PDF, and web pages delivered with one tap. Offline ledger, AI chat, installable as a PWA.

Gateway

🔌 osmind-gateway

The phone's single write-path into the vault: a local HTTP gateway with token-paired auth and a content extraction pipeline. Input never gets lost.

Memory

🗄️ Memory engine

Dual-track memory: a dynamic daily stream plus a curated static knowledge base, indexed into semantic memory banks the AI can recall from.

Night Butler

🌙 Hermes

The automation layer — four scheduled jobs that patrol the inbox, sync memory, back up to NAS, and distill raw notes into a wiki. All while I sleep.

Launch Site

🌐 NP-OS

The product's own bilingual landing page — positioning, copy, design, and build. Because a system this opinionated deserves a proper brand.

The Night Shift

The best assistant works while you're asleep.

Four automated jobs run on a fixed schedule, every single day, without being asked. This is the part that makes it an operating system rather than a folder of notes.

How It Was Built

One person. An AI dev team. Brand thinking applied to software.

I'm not a traditional software engineer — I'm a brand strategist who learned to direct AI agents the way I direct a creative team. I wrote the product vision, the information architecture, and the design system; AI agents wrote code under review, iteration by iteration. Every screen, every doc page, every line of onboarding copy went through the same standard I hold client work to.

The result shipped: a versioned open-source release with an installer, documentation, a mobile app, and its own marketing site. The same playbook I use for brands — positioning → identity → content → distribution — works for products.

What I Learned

Building for yourself is the hardest client brief.

✓ What Worked

Subtraction as philosophy — one inbox beat every multi-folder system I'd tried
Plain Markdown + zero dependencies = a product that can't be killed by a vendor
Directing AI agents scales one person into a full product team
Dogfooding daily — I am user #1, so feedback loops are instant

✗ What Was Hard

Mobile is its own world — sync, auth, and offline cost more than all desktop features combined
Automation that touches your real data demands paranoid backup design first
Scope creep is brutal when the client is you — versioned releases forced discipline

"For years I told clients that a brand is a system, not a logo. Building Personal OS proved the inverse: a product is a brand, not a codebase. Positioning, naming, onboarding, story — that's what makes software feel inevitable. And it's the same craft."
