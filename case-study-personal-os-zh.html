Personal OS

问题

所有笔记系统都要求你「先想清楚再记」。这是本末倒置。

14 年品牌工作产生的零散思考多到离谱——半夜冒出的营销点子、堵车时想起的客户待办、随手记在聊天软件里的开销。我试过的每一个效率工具都提出同样的要求：先决定放哪里。哪个文件夹、什么标签、用哪个模板。认知负担恰恰发生在你注意力最稀缺的那一刻。

所以我把它反过来：一个收件箱，零决策。系统自己想清楚剩下的事——还有一位 AI 夜间管家，在我睡觉时把一切收拾干净。

核心理念

只管丢进去，OS 替你分拣。

用户唯一需要的动作，就是把想法丢进 Inbox——文字、语音、PDF、网页，电脑或手机都行。AI 管线把每一条输入拆分成结构化实体，自动归档到五大支柱 Markdown 库的正确位置。

「今天定下了项目架构。记得明天给服务器换证书。午饭花了 38 块。」
↓
📓 日记
项目架构决策，记入今日笔记
✅ 待办
「服务器换证书」——截止日自动换算为明天
💸 账单
午餐 38 元，自动入账

所有数据都存在我完全拥有的纯 Markdown 文件里——没有私有数据库，没有订阅锁定，未来 30 年用任何编辑器都能打开。

我做了什么

不是一个 App，是有六个器官的操作系统。

每一层都可替换、可扩展、可自托管。我用做品牌系统的方式来设计它：每个组件职责清晰，彼此接口分明。

核心 · v0.7

🧠 personal-os

桌面端核心：五大支柱 vault 模板、零依赖的 rtk CLI 引擎、自研 Obsidian 看板插件、一条命令完成安装。

移动端

📱 OSMIND App

口袋里的捕获终端——文字 / 语音 / PDF / 网页一键投递，离线账本，AI 聊天，PWA 直接装进主屏幕。

网关

🔌 osmind-gateway

手机写入 vault 的唯一通道：本地 HTTP 网关 + 配对 Token 鉴权 + 内容提取管线。输入永不丢失。

记忆引擎

🗄️ 双轨记忆

dynamic 动态日流 + static 静态知识库双轨并行，索引进语义记忆库，AI 随时召回。

夜间管家

🌙 Hermes

自动化层——四个定时任务：巡检收件箱、同步记忆、备份到 NAS、把生料笔记蒸馏成 Wiki。全部在我睡觉时完成。

官网

🌐 NP-OS

产品自己的双语官网——定位、文案、设计、开发一手包办。这么有态度的系统，配得上一个正经的品牌门面。

夜班时刻表

最好的助理，在你睡着时工作。

四个自动化任务按固定时刻表运行，每天如此，无需吩咐。正是这一层，让它成为操作系统，而不只是一堆笔记文件夹。

怎么做出来的

一个人，一支 AI 开发团队，用品牌思维做软件。

我不是科班软件工程师——我是一个学会了「指挥 AI 代理」的品牌策略师，方式和指挥创意团队一模一样。产品愿景、信息架构、设计系统由我定；AI 代理在我的评审下写代码，一轮一轮迭代。每一个界面、每一页文档、每一句新手引导文案，都按我交付客户作品的标准来要求。

结果是真实交付：带安装器的开源正式版、完整文档、手机 App，还有它自己的营销官网。我做品牌的那套打法——定位 → 识别 → 内容 → 分发——对产品同样成立。

我学到了什么

给自己做产品，是最难伺候的客户简报。

✓ 有效的

做减法是美德——一个收件箱，胜过我试过的所有多文件夹系统
纯 Markdown + 零依赖 = 不会被任何厂商杀死的产品
指挥 AI 代理，能把一个人放大成一支完整的产品团队
每天吃自己的狗粮——我就是 1 号用户，反馈闭环即时生效

✗ 艰难的

移动端是另一个世界——同步、鉴权、离线的成本超过桌面端全部功能之和
碰真实数据的自动化，必须先有偏执级的备份设计
客户是自己时，需求蔓延最凶猛——版本化发布逼出了纪律

「这些年我一直告诉客户：品牌是一个系统，不是一个 Logo。做 Personal OS 让我验证了反命题：产品是一个品牌，不是一堆代码。定位、命名、引导、叙事——这些才是让软件『理所当然』的东西。而这，是同一门手艺。」
